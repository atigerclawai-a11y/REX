CORRECTIONS TO THE PROPOSAL
================================================================================

CORRECTION 1 — Confidence thresholds are wrong (CRITICAL)
The system summary states: >= 90% auto-route / 70-89% review / <70% escalate.
Governing doctrine states: >= 0.85 route / 0.60-0.84 review / <0.60 unresolved.
These are different thresholds. The system must use doctrine thresholds. All
routing logic must be updated to match doctrine. This affects Patch 4
(handwriting), Patch 6 (classification stability), and the core confidence
router.

CORRECTION 2 — Patch 3 framing is inverted
Patch 3 says "Do NOT use sign-in alone as final state." This contradicts
doctrine. Doctrine says: Calendar -> Sign-in -> Attendance truth. Sign-in IS
the truth. Calendar is planning. The reconciliation layer flags calendar
deviations for review only. Sign-in wins unconditionally. Patch 3 should read:
sign-in is the attendance authority; reconciliation flags calendar deviations
for review only.

CORRECTION 3 — Flag queue root cause is wrong
The 24 pending flags are not UUID-format doc_ids conflicting with the integer
processor. Live inspection shows 23 of 24 pending flags have doc_id=None
entirely, with UUID-format flag_id fields. These were generated by a different
path (not Paperless) and were never matched to a Paperless document. The
processor skips them because there is no doc_id — not because of a format
mismatch.
Fix: processor must handle doc_id=None by doing candidate_name lookup against
client_menus directly instead of Paperless doc lookup.
Additionally: the status field in goj_menu_flags_queue.json is corrupted. 20
flags show resolved=True but status="low" or status="medium" — status was never
updated when resolved. Any report reading the status field will see 44 "pending"
when only 24 are actually pending. One-time normalization required: set
status="resolved" where resolved=True.
