## Maintained by: Hermes | Effective: June 1, 2026

## The One Rule

**Any new file created in `~/Desktop/REX/` on or after June 1, 2026 must start with `CC_`.**

Pre-existing files (created before June 1, 2026) are grandfathered. They keep their original names. The overseer auto-detects modification time and never flags them.

---

## Naming Convention Details

The `CC_` prefix stands for **Canonical Cowork** — it signals that the file is intentionally authored and tracked in the GHS system.

### Format

```
CC_<descriptive_name>.<ext>
```

Good examples:
- `CC_gateway_watchdog.py`
- `CC_fix_telegram_bot.command`
- `CC_PHASE_STATUS.md`
- `CC_doc_overseer.py`

Bad examples (will trigger alert):
- `goj_daily_scheduler.py` — no CC_ prefix, post-June-1
- `reauth_google_full.py` — no CC_ prefix, post-June-1
- `fix_thing.command` — no CC_ prefix, post-June-1

### Case sensitivity

The prefix must be uppercase `CC_`. Lowercase `cc_` does not satisfy the rule and will be flagged.

## Violation Types and Severity

### 🔴 ALERT — Missing CC_ prefix (naming)
**Trigger:** A new file (post-June-1) in REX root or `backend/` does not start with `CC_`.  
**Action:** Rename the file to add `CC_` prefix. Add to whitelist if exemption is justified.  
**Telegram:** Yes — sent immediately on detection.

### 🟡 ALERT — Duplicate content
**Trigger:** Two files in REX (outside of CC_-prefixed archive dirs) have identical SHA-256 hashes.  
**Action:** Review both files. Delete the redundant one manually if confirmed duplicate.  
**Telegram:** Yes — on new detection.

### 🔵 WARNING — Orphaned documentation
**Trigger:** A new `.md` file in the REX root is not mentioned by filename in either `CC_MASTER_BUILD_LOG.md` or `CC_PHASE_STATUS.md`.  
**Action:** Add a reference entry in the appropriate build log. Or whitelist if it's intentionally standalone.  
**Telegram:** Yes — on new detection.

### 🟠 WARNING — Oversized log
**Trigger:** Any `.log` file exceeds 50 MB.  
**Action:** Archive or truncate the log manually. Consider adding log rotation to the service that writes it.  
**Telegram:** Yes — on new detection.

### ⚪ INFO — Empty file (0 bytes)
**Trigger:** Any non-hidden file outside CC_-prefixed archive dirs has 0 bytes.  
**Action:** Investigate — may be a failed write, a placeholder, or a truncated file.  
**Telegram:** Yes — on new detection.

## How to Suppress a False Positive

Add the **exact filename** (basename only, not full path) to the whitelist file:

```
~/Desktop/REX/.doc_overseer_whitelist
```

Format — one filename per line, `#` for comments:

```
# Overseer whitelist — entries here are never flagged
reauth_google_full.py        # legacy one-off, pre-convention
goj_daily_scheduler.py       # auto-generated by n8n, naming controlled externally
docker-compose.yml           # third-party format, CC_ prefix breaks Docker tooling
```

**Whitelist is for exceptions, not excuses.** If you're adding more than 3 entries a week, something is wrong with the process upstream.

## How to Install the LaunchAgent

The plist is at `~/Desktop/REX/com.ghs.doc-overseer.plist`. It is **NOT pre-installed** — run these steps when ready to activate:

**Step 1 — Verify the bot token is accessible**

The Telegram token must be in the environment. Check it:
```bash
echo $HERMES_BOT_TOKEN
```

If empty, either export it in your `.zshrc` or uncomment and fill the `HERMES_BOT_TOKEN` key in the plist's `EnvironmentVariables` dict.

**Step 2 — Copy plist to LaunchAgents**

```bash
cp ~/Desktop/REX/com.ghs.doc-overseer.plist \
   ~/Library/LaunchAgents/com.ghs.doc-overseer.plist
```

**Step 3 — Load it**

```bash
launchctl load ~/Library/LaunchAgents/com.ghs.doc-overseer.plist
```

**Step 4 — Verify it's running**

```bash
launchctl list | grep doc-overseer
# Should show the label with PID 0 (sleeping between runs) or a live PID
tail -f ~/Desktop/REX/logs/doc_overseer_launchd.log
```

**To stop the daemon:**

```bash
launchctl unload ~/Library/LaunchAgents/com.ghs.doc-overseer.plist
```

**To restart after editing the plist:**

```bash
launchctl unload ~/Library/LaunchAgents/com.ghs.doc-overseer.plist
launchctl load ~/Library/LaunchAgents/com.ghs.doc-overseer.plist
```

## State and Logs

| File | Purpose |
|------|---------|
| `~/Desktop/REX/logs/doc_overseer.log` | Timestamped violation log (append-only) |
| `~/Desktop/REX/logs/doc_overseer_launchd.log` | launchd stdout/stderr (script print output) |
| `~/Desktop/REX/logs/.doc_overseer_state.json` | Known violations — used to detect NEW violations and avoid repeat alerts |
| `~/Desktop/REX/.doc_overseer_whitelist` | Manual exemptions — one filename per line |

The state file tracks all known violations. When the daemon runs and finds a violation already in the state file, it is **silent** — no new log entry, no Telegram. Only genuinely new violations trigger alerts.

To reset and re-alert all violations (useful after cleanup):
```bash
rm ~/Desktop/REX/logs/.doc_overseer_state.json
```
